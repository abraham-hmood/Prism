# Zombie Studio

Procedural, code-only zombie meshes, textures, rigs and animations for the
**Zombies** minigame. No downloaded models, no downloaded images: every vertex,
pixel and keyframe is generated by these two Python files.

## Files

| File | Purpose |
| --- | --- |
| `zombie_studio.py` | Anatomy, fused garments, carved head, 2048² PBR textures, studio renders |
| `export_game_assets.py` | Joins the body, builds the skeleton, keys Walk/Crawl, exports GLB, bakes sprites |

## Rebuild

```bash
# authoring renders (three-quarter / front / closeup / crawl)
"C:/Program Files/Blender Foundation/Blender 5.2/blender.exe" -b \
  --python tools/zombie_studio/zombie_studio.py -- --variant male --pose stand --view closeup

# every rigged game asset + sprite
"C:/Program Files/Blender Foundation/Blender 5.2/blender.exe" -b \
  --python tools/zombie_studio/export_game_assets.py
```

Outputs:

- `tools/zombie_studio/game_assets/zombie_{male,female}_{stand,crawl}.glb`
  — one skinned mesh, one animation each (`Walk` or `Crawl`), 17 bones.
- `app/src/main/assets/zombie/sprites/zombie_{male,female}_{stand,crawl}.png`
  — 768×1536 transparent renders used by the built-in Android renderer.
- `tools/zombie_studio/out/textures/*.png` — 2048² skin/cloth, 1024² leather/hair,
  albedo + normal + roughness.
- `tools/zombie_studio/out/*.png` — studio turntable and animation strips.

## How the model is built

1. **Skull**: a lofted anatomical profile (17 rings) with separate brow, cheek,
   jaw, chin, nose, lips, ears and eyelids.
2. **Fusion**: all of those are joined and voxel-remeshed into one continuous
   skin, so features are not stickers on a sphere.
3. **Carving**: real boolean openings for the eye sockets, mouth, nostrils and
   ear conchae.
4. **Surface**: displaced skin creases (nasolabial, crow's feet), stubble patches,
   material-painted lesions, blood runs.
5. **Garment**: the jacket, trousers, sleeves and trouser seat are fused per
   garment, then creased with joint folds (elbows, knees, waist) and given
   material-painted blood, ragged tears and torn flesh beneath.
6. **Skinning**: every vertex is bound to its nearest bone; the skull and boots
   stay rigid, which survives the crawl pose.
7. **Animation**: 25-frame cycles at 24 fps. `Walk` swings thighs/shins and
   counter-swings arms; `Crawl` alternates reaching arms and dragging legs.

## Integration

- **Android minigame**: `FpsGameView.drawZombie` loads the 768×1536 sprite from
  assets and draws it with the correct alpha and tint for brutes/spitters. The
  old rectangle zombie is only a fallback if the asset is missing.
- **Godot export**: `zombie_male_stand.glb` and `zombie_male_crawl.glb` are copied
  into `C:/Users/bremo/Prism/ZombiesCraft/godot/assets/models/`. Open the project
  and drag the GLB into a scene; the `Walk`/`Crawl` action comes with it.

## Known limits

- This is a **stylised, game-resolution** zombie, not a photoreal scan. The
  reference images are rendered concept art with subsurface skin, cloth
  micro-fibres and sculpted wrinkles; matching that exactly is not reachable from
  primitive/loft code alone.
- The crawl silhouette is the weakest pose: the head sits close to the chest and
  the neck reads thick. The standing poses are the strongest.
- Each GLB is 60–68 MB at ~600k vertices. They are kept out of the APK; the app
  ships the sprites, and the GLBs are for desktop Godot. Decimate the mesh before
  shipping if APK size matters.
